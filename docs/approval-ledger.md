# 承認の台帳の形（2026-11-02 に決めた）

まちしるべは、集めた情報のうち「危ない所だけ人が確かめ、ほかは自動で承認する」。
その記録の形を、画面を作る前に決めておく。あとの日に直したら、この文書も直す。

## 1. 記録は3つに分ける

| 記録 | 1件が表すもの | いくつできるか |
|---|---|---|
| 情報源カード | 「このページ（資料）を、こう読む」というひとまとまり | 町ごとに数十 |
| 答え | 物差しの問い1つへの答え（数字か文） | 町ごとに数十〜数百 |
| 調査の記録 | 町を1回調べたときの流れ全部 | 町ごとに1回ずつ増える |

承認するのは、ふだんは**情報源カード**（1回 OK すれば、そこから出る答えは自動で承認）。
答えを1件ずつ見るのは、食い違い・気をつけたい話題など、下の「人が見るもの」だけ。

## 2. 情報源カードが持つもの

| 項目 | 中身 | 公開してよいか |
|---|---|---|
| 番号 | カードごとの通し番号 | 公開 |
| 町 | どの町のためのカードか（市で共通のものは市） | 公開 |
| 範囲 | 段とコード（`japan`・`muni:28109`・`town:281090990`）。誰が扱えるかを決めるもと（8 章） | 公開 |
| 名前 | 人が読んで分かる名前（例「町の防災計画（PDF）」） | 公開 |
| URL | 元のページ・ファイルの場所 | 公開 |
| 形 | HTML・PDF・CSV・Excel・地図のタイル・API | 公開 |
| 出した人 | 国・県・市町村・決まった事業者のどれか | 公開 |
| 確かめた日 | 最後に中身を見た日 | 公開 |
| 時点 | データ自身の時点（「令和8年1月1日現在」など） | 公開 |
| 使ってよい範囲 | CC BY・政府の公共データ利用規約・転載禁止・書いていない | 公開 |
| 読み方 | どこから何を取るか（表の何列目・PDF の章など） | 公開 |
| 読み方の版 | 読み方を直したら1つ増やす | 公開 |
| 自動か手動か | このカードから出る答えを自動で承認してよいか | 公開 |
| 決めた記録 | いつ・誰が・なぜ OK したか（理由を1行） | 公開 |
| 取ったときの様子 | robots.txt の判断・応答の番号・間隔 | 公開 |
| 読んだ中身そのもの | ページや PDF の本文 | **手元だけ**（local/） |

## 3. 答えが持つもの

| 項目 | 中身 | 公開してよいか |
|---|---|---|
| 番号 | 答えごとの通し番号 | 公開 |
| 町・問い | どの町の、どの問い（C1〜C18 や型の問い）への答えか | 公開 |
| 値 | 数字と単位、または文 | 公開（承認後） |
| 時点 | その値がいつのものか | 公開 |
| 出典の場所 | どのカードの、どこか（PDF の何ページ・表の何行目） | 公開 |
| 点数 | 0〜3点、または「保留」「町の人に聞く」 | 公開 |
| 作り方 | 読んで取った／計算した（計算は式と材料も） | 公開 |
| 元にした答え | この答えを作るのに使った答えの番号（まとめの文・訳・クイズ用） | 公開 |
| 状態 | 下の「状態の移り変わり」 | 公開 |
| なぜ人が見るか | 手動に回した理由（1行） | 公開 |
| 決めた記録 | いつ・誰が・何を決めたか（理由を1行） | 公開 |
| 引用した元の文 | 照らし合わせに使った原文 | **手元だけ**（local/） |

## 4. 状態の移り変わり

```
集めた
 ├→ 自動で承認 ──────────→ 公開（ページに出る）
 └→ 確かめ待ち（保留）
       ├→ OK ───────────→ 公開
       ├→ 直して → 集め直して、また確かめ待ち
       ├→ 出さない（理由を残す）
       └→ 分からない（理由を残す。町の人に聞くことの一覧へ）

公開 → 取り消し（ページから下げる。記録は消さず、いつ・誰が・なぜを残す）
```

- 「調べ終わり」と「全部承認済み」は別。手動のものが残っていても調査は終わる
- 取り消しは3通り：答え1件だけ／情報源カードごと（そこから出た答えを全部下げ、自動承認も止める）／
  元の答えごと（それを元に作った文・訳・クイズも一緒に下げる）
- 権利の無い文や個人の情報を出してしまったときは、ページから消すだけでは足りない。
  履歴の書き換えと、必要なら GitHub への削除の依頼。手順は別の文書に書く

## 5. 自動で承認してよい条件（全部そろったとき）

1. 出典が公式（lg.jp・go.jp・決まった事業者）
2. 形のチェックが通る（日付・曜日・町丁目の一覧にある住所など）
3. 試しの答えと合う
4. 別の情報源と食い違わない
5. 確かめ役が、引用した元の文と照らして合っていると言う
6. 確かめた日が、決めた日数以内

## 6. 人が見るもの（自動にしない）

- 使ってよいかの判断（「要問い合わせ」・転載禁止・条件が書いていない）＝権利は任せない
- 公式どうしの食い違い（市と県で避難所や想定が違う）
- 境目があいまい（住所が2つの区域にまたがる）
- 人が写る・個人に関わるもの
- 問い合わせ・連絡（外へ出す行動）
- 気をつけたい話題（選挙・事件・医療・お金・基地・原発）
- その町の「壁」の見立て（物差しの C17）

手動のものも、全件ではなく抜き取りで数件見る。承認できるのは作者だけ（手元の画面だけに出る）。

## 9. 作ったもの（2026-11-02）

- `scripts/ledger.mjs`：台帳の部品。`add`（一覧に足す）・`decide`（OK・直して・出さない・分からない・元に戻す）・
  `exportPublic`（公開してよいものだけ書き出す）・`can`（権限の判定）
- 置き場所：`local/ledger/items.json`（1件ずつ。引用した元の文も入る）・`local/ledger/log.jsonl`（決めた記録。消さずに足す）は公開しない。
  OK と自動承認の答えだけを `site/data/answers/{市区町村コード}.json` に、件数・理由・出典の URL だけを `site/data/review.json` に書き出す
- 画面：`site/review.html`。手元の画面では決められ、押したあと6秒は「元に戻す」が出る。直して・出さない・分からないは理由を1行書く。
  公開のサイトでは件数と、人が見たものの理由・出典の URL だけ（元の文は出さない）
- 確かめたこと：OK で公開用の答えに出る・元に戻すと消える・出さないの理由が記録に残る・公開の一覧に元の文が入らない

## 8. 誰が扱えるか（2026-11-02 に足した）

- 情報源カード・答え・点検の結果・確かめる一覧の1件は、どれも「範囲」を持つ（段とコード）
- 決めた記録・取り消しの記録の「誰が」は利用者の番号で残す。いまは作者1人（`owner`）
- 扱ってよいかは、権限の判定1か所で決める。いまは `owner` ならすべての範囲でよい
- 将来：段ごとの管理者（全国・市区町村・町・字）を割り当てる表を足す。上の段の管理者は下の段も扱える。
  公開のサイトでは扱えない（見るだけ）ので、そのときはログインと書きこみを受けるサーバーが要る（`docs/decisions.md`）

## 7. 公開するときの決まり

公開のサイトに出すのは、承認された答えと、情報源カードの公開してよい項目だけ。
確認の一覧（/review）と調査の記録（/runs/）は、件数・理由・出典の URL・読んだページ数・
かかった時間・費用だけを出す。読んだ本文や引用した原文は手元（local/）に置いたままにする。
